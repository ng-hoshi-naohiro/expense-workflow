## 1. システム概要

### 1.1 目的

複数施設を運営する事業体において、一般経費（施設備品購入・出張交通費・採用関連費等）の事前申請から承認までを電子化するワークフローシステムを構築する。過去に導入した別システムが「使いこなせず形骸化」した経緯があるため、PC操作に習熟していない現場社員でも直感的に操作できるUIを最優先とする。

### 1.2 主要機能

| 区分 | 機能 |
|------|------|
| 申請 | 経費申請の作成、添付書類のアップロード（カメラ撮影含む）、OCR連動の自動入力、下書き自動保存、過去申請の複製 |
| 承認 | 通知から最短5〜8秒で完了するワンタップ承認、生体認証（WebAuthn）、申請内容の自動チェック・アラート |
| 進捗管理 | 申請の進捗マップ、承認の滞留状況可視化、未提出リマインダー |
| 分析 | 経営ダッシュボード（施設×カテゴリ×月次）、予算管理・上限アラート |
| 連携 | バクラク（既存・税理士法人指定）、勘定奉行クラウド、LINEWORKS |
| 管理 | 操作履歴の保存（行政の実地指導・会計監査対応）、マスター管理 |

### 1.3 動作環境

| 項目 | 内容 |
|------|------|
| アプリケーション形態 | Webアプリケーション（PWA化を推奨） |
| 想定ブラウザ | iOS Safari（16以降）、Android Chrome、PC（Chrome／Edge／Safari） |
| 主要操作端末 | スマートフォン（申請者・承認者）、PC（経理・管理者） |
| 認証方式 | WebAuthn（FaceID／TouchID／指紋認証）／パスワード（フォールバック） |

## 2. 対象ユーザーとロール

| ロール | 主な利用者 | 主な操作 |
|--------|-----------|---------|
| 申請者 | 施設長、本部役職者 | 経費申請の作成・送信、申請履歴の参照 |
| 承認者 | 本部役職者、上位管理者 | 申請の承認・差戻し |
| 経理担当者 | 経理部 | 承認済データの会計連携、月次集計、予算管理 |
| 管理者 | 管理部門 | マスター管理、ユーザー管理、監査ログ参照 |

申請者と承認者は兼任が前提（本部役職者は自身が申請者かつ他の申請の承認者）。

## 3. デザイン仕様

### 3.1 デザインコンセプト

**「業務に誠実な、上品な道具」**

業務システムであり、信頼感・正確性・落ち着きが最優先。ただし無機質ではなく、和洋折衷の上質さを感じさせるトーンを目指す。介護施設運営という事業特性に合う、誠実で控えめな佇まい。

### 3.2 カラーパレット

CSS変数として定義し、ライトテーマで運用する。

| 役割 | 変数名 | カラーコード | 用途 |

## 4. UI設計原則

PC操作に習熟していないユーザーが申請者となる前提で設計する。

### 4.1 一画面一目的の原則

1つの画面では1つの主要タスクのみを扱う。情報過多を避け、次に何をすればよいかを常に明示する。

### 4.2 アイコン単独使用の禁止

すべての操作要素は「アイコン＋テキストラベル」のセットで提示する。アイコンのみのボタンは禁止する。理由：アイコンの意味は学習を要するため、PC不慣れ層には伝わりにくい。

### 4.3 タップ領域の確保

ボタンの最小タップ領域は48px×48px。スマートフォン操作時の誤タップを防止する。

### 4.4 確認ダイアログの徹底

申請送信、承認、差戻し、削除等の不可逆操作の前には必ず確認ダイアログを表示する。「よろしいですか？」ではなく「○○を承認します。よろしいですか？」のように具体的な対象を明示する。

### 4.5 進捗・状態の常時可視化

ユーザーが「今、自分はどの段階にいるのか」を常に把握できるようにする。フォームには「ステップ1/3」のような進捗表示、申請には進捗マップを設置する。

### 4.6 エラーメッセージは原因と対処を明示

「エラーが発生しました」のような抽象的な表現は禁止。「金額が読み取れませんでした。明るい場所で撮り直してください」のように、原因と次のアクションを必ず伝える。

### 4.7 アクセシビリティ

- カラーコントラスト比はWCAG AA基準（4.5:1以上）を満たす
- 色のみで状態を伝えない（テキストやアイコンを併用）
- フォーカスインジケーターを明確に表示

### 4.8 レスポンシブ対応

- スマートフォン（375px〜）：申請者・承認者の主要動線
- タブレット（768px〜）：補助
- PC（1024px〜）：経理・管理者業務、ダッシュボード

スマホ優先で設計し、PCはレスポンシブ拡張とする（モバイルファースト）。

## 7. 画面別詳細仕様

### 7.1 SC-01：ログイン画面

#### 7.1.1 画面の目的

ユーザーが本システムにログインするための入り口。初回はメールアドレス＋パスワードで認証し、デバイス登録（SC-02）へ誘導する。2回目以降は登録済みデバイスでの生体認証ログインを優先する。

#### 7.1.2 画面構成

| エリア | 内容 |
|--------|------|
| ロゴ・サービス名 | 中央上部、明朝体で「ワークフロー」 |
| サブタイトル | 「一般経費承認システム」14px |
| ログインフォーム | 中央配置、最大幅400px |
| 生体認証ボタン | 登録済みデバイスでアクセスした場合に最上部に表示 |
| メールアドレス入力欄 | プレースホルダー「会社のメールアドレス」 |
| パスワード入力欄 | パスワード表示／非表示切替ボタン付き |
| ログインボタン | プライマリボタン、横幅100% |
| 補助リンク | 「パスワードを忘れた方」（小さく下部） |

#### 7.1.3 主要動作

- 生体認証ボタンタップ → WebAuthnのブラウザAPIを呼び出し → OS生体認証ダイアログ → 成功時にホーム画面へ遷移
- メール＋パスワード入力 → ログインボタン → サーバ認証 → 初回なら SC-02 へ、2回目以降ならホーム画面へ

#### 7.1.4 デザイン上の留意点

- 背景は `--paper` をベースに、上下にうっすらグラデーション
- フォームカードは `--screen` で配置
- 業務システムらしさを保ちつつ、入り口として適度な品格を持たせる

### 7.2 SC-02：デバイス登録画面

#### 7.2.1 画面の目的

初回ログイン時に、現在使用しているデバイスをWebAuthnで「承認端末」として登録する。1回限りの操作で、所要時間は約1分。

#### 7.2.2 画面構成

| エリア | 内容 |
|--------|------|
| 説明セクション | 「このデバイスを承認用端末として登録します」というタイトルと説明文 |
| メリットの説明 | 「次回からパスワード入力が不要になります」等を3項目程度 |
| デバイス情報の自動表示 | 「iPhone Safari」「Windows Chrome」等の自動検出表示 |
| 登録ボタン | プライマリボタン「このデバイスを登録する」 |
| スキップリンク | 「あとで登録する」（小さく下部、推奨はしない旨注記） |

#### 7.2.3 主要動作

- 登録ボタンタップ → WebAuthn `navigator.credentials.create()` 呼び出し → OSの生体認証ダイアログ → 成功時にホーム画面へ遷移
- 失敗時は具体的な原因（「生体認証が設定されていません」等）を表示

### 7.3 SC-03：ホーム画面

#### 7.3.1 画面の目的

ログイン後の起点画面。申請者・承認者として「次に何をすべきか」が一目で分かる構成にする。

#### 7.3.2 画面構成

| エリア | 内容 |
|--------|------|
| ご挨拶セクション | 「○○さん、こんにちは」（時間帯で挨拶語を変える） |
| 未提出リマインダー | 月末3日前以降に表示する警告カード「未提出の精算が○件あります」、タップで履歴画面へ |
| クイックアクション | 「新しく申請する」（最大ボタン）、「前回コピー」（過去申請の最頻出をワンタップ複製） |
| 承認待ち件数 | 承認者の場合「○件の承認待ちがあります」カード、タップで承認待ち一覧へ |
| 進行中の申請 | 自分の申請のうち、承認中の最大3件をリスト表示。各カードに進捗マップのミニ表示 |
| 最近の活動 | 直近1週間の申請・承認履歴をタイムライン形式で表示 |

#### 7.3.3 主要動作

- 「新しく申請する」 → SC-04 申請カテゴリ選択画面へ
- 「前回コピー」 → 確認ダイアログ → SC-05 申請フォーム（前回値プリセット）へ
- 「承認待ち件数」カード → SC-08 承認待ち一覧画面へ
- 進行中の申請カードタップ → SC-07 申請詳細・進捗マップ画面へ

#### 7.3.4 レスポンシブ仕様

- スマホ：縦1カラム、各カードフル幅
- PC：「クイックアクション」を上部に大きく配置、その下に2カラム（左：自分の申請、右：承認待ち）

### 7.4 SC-04：申請カテゴリ選択画面

#### 7.4.2 画面構成

### 7.5 SC-05：申請フォーム画面

#### 7.5.1 画面の目的

選択されたカテゴリに応じた申請内容を入力する。本システムの中核画面。

#### 7.5.2 画面構成（共通要素）

| エリア | 内容 |
|--------|------|
| ステップ表示 | 画面上部「ステップ 1 / 3：内容入力」のような現在地表示 |
| 下書き保存表示 | ヘッダー右上「○秒前に自動保存しました」のラベル |
| カテゴリ別フォーム | 後述 |
| 添付書類エリア | カメラ起動ボタン＋ファイル選択ボタン、撮影済み画像のサムネイル一覧 |
| OCR連動の自動入力 | 撮影／アップロード後、金額・日付・店舗名が自動入力される（編集可） |
| 写りチェック結果 | 撮影直後に「ピンボケしています」「明るくしてください」等を即時表示 |
| 進捗ボタン | 「下書き保存」「次へ」「前へ」 |

#### 7.5.3 カテゴリ別フォーム

**施設備品購入:**

| 項目 | 入力種別 | 必須 |
|------|---------|------|
| 施設名 | プルダウン（マスター連動） | ※必須 |
| 購入品目 | テキスト | ※必須 |
| 用途 | テキストエリア | ※必須 |
| 業者名 | テキスト | ※必須 |
| 金額（税込） | 数値（OCRで自動入力） | ※必須 |
| 購入希望日 | 日付選択 | ※必須 |
| 見積書／領収書 | カメラ＋ファイル添付 | ※必須 |

**出張交通費精算:**

| 項目 | 入力種別 | 必須 |
|------|---------|------|
| 出張日 | 日付範囲 | ※必須 |
| 出張先 | テキスト | ※必須 |
| 目的 | テキスト | ※必須 |
| 経路・金額 | 行追加可能なリスト | ※必須 |
| 領収書 | カメラ＋ファイル添付 | ※必須 |

**採用関連費:**

| 項目 | 入力種別 | 必須 |
|------|---------|------|
| 施設名 | プルダウン | ※必須 |
| 費用種別 | プルダウン（紹介手数料／求人広告／その他） | ※必須 |
| 業者名 | テキスト | ※必須 |
| 金額（税込） | 数値（OCRで自動入力） | ※必須 |
| 請求書／契約書 | カメラ＋ファイル添付 | ※必須 |

#### 7.5.4 カメラ起動と写りチェックのフロー

1. カメラボタンタップ → ブラウザのMediaDevices APIでカメラ起動
2. シャッター → 撮影直後にクライアントサイドでブレ・暗さ・はみ出しを判定
3. 問題があれば「ピンボケしています。撮り直しますか？」と即時表示。「撮り直す」「そのまま使う」を選択
4. OKならサーバへ画像送信 → OCR処理 → 金額・日付・店舗名を抽出 → フォームへ自動入力
5. ユーザーは内容を確認・修正

#### 7.5.5 主要動作

- 「次へ」ボタン → 入力内容のサマリ確認画面（SC-05のステップ2）
- 確認画面で「申請する」ボタン → 確認ダイアログ → 申請送信 → SC-07 申請詳細画面へ
- 入力中に画面遷移したり通信が切れても、入力内容は10秒ごとに自動保存される

### 7.6 SC-06：申請履歴一覧画面

#### 7.6.1 画面の目的

- 金額は等幅フォント（JetBrains Mono）で右揃え、桁を揃える

### 7.7 SC-07：申請詳細・進捗マップ画面

#### 7.7.1 画面の目的

特定の申請の詳細を表示し、誰のところで止まっているか／いつ承認されたかを「進捗マップ」で可視化する。承認の滞留状況も一目で把握できる。

#### 7.7.2 画面構成

| エリア | 内容 |
|--------|------|
| ヘッダー | 申請ID（等幅フォント）、ステータスバッジ、申請日 |
| 進捗マップ | 横並びのステップインジケーター（申請→1次承認→2次承認→完了） |
| 各ステップ表示 | 名前、役職、処理状況、処理日時、滞留日数（3日以上は警告色） |
| 申請内容詳細 | 入力されたフォーム内容を表示形式で |
| 添付書類 | サムネイル、タップで拡大プレビュー |
| コメント・差戻し履歴 | 承認者からのコメントを時系列で表示 |
| アクションボタン | 申請者の場合：取下げ、修正再申請。承認者の場合：承認、差戻し |

#### 7.7.3 進捗マップの仕様

```
[申請]----[1次承認]----[2次承認]----[完了]
  済        進行中         待機         待機
 5/7      5/7 14:23                       
                ↓
            田中部長
            （滞留 2日）
```

進行中ステップは `--accent` でハイライト、滞留3日以上は警告アイコン＋「滞留 ○日」表示。完了ステップは `--success` のチェックマーク。

#### 7.7.4 主要動作

- 承認者の場合「承認する」 → SC-09 承認詳細画面へ（生体認証フロー開始）
- 申請者の場合「取下げ」 → 確認ダイアログ → 取下げ完了

### 7.8 SC-08：承認待ち一覧画面

#### 7.8.1 画面の目的

#### 7.8.2 画面構成

| 件数サマリ | 「○件の承認待ち」「うち滞留中 ○件」 |
| フィルタ | カテゴリ、金額帯、申請者、滞留日数 |
| 申請カード | 各カードに申請者、カテゴリ、金額、申請日、滞留日数バッジ |
| 自動チェック・アラート | 「金額が高額です」「同一業者へ月3件目」等のラベルが該当案件に表示 |
| 並び替え | 「滞留日数順」「金額順」「申請日順」 |

#### 7.8.3 自動チェック・アラートの表示

| アラート種別 | 表示色 | ラベル |
|------------|--------|--------|
| 金額閾値超 | `--warning` | 「30万円超」 |
| 同一業者頻度 | `--warning` | 「同一業者へ月3件目」 |

これらは承認時の判断材料として、該当案件のカード上部に小さく表示する。

#### 7.8.4 主要動作

- カードタップ → SC-09 承認詳細画面へ

### 7.9 SC-09：承認詳細・ワンタップ承認画面

#### 7.9.1 画面の目的

通知から最短5〜8秒で承認を完了させる。WebAuthn生体認証で本人確認＋電子署名による監査証跡を実現する。

#### 7.9.2 画面構成

| エリア | 内容 |
|--------|------|
| 承認待ちタグ | 上部に「承認待ち」バッジ |
| 申請タイトル | 大きめのテキストで「○○施設 備品購入」 |
| 金額（強調表示） | 明朝体32px以上で大きく表示「¥12,000」 |
| 申請メタ情報 | 申請者、用途、申請日 |
| 添付書類リンク | 「領収書を見る」（タップで拡大プレビュー） |
| AI推定勘定科目 | 自動仕訳の推定結果と信頼度表示「推定：消耗品費（信頼度 高）」 |
| 自動チェックアラート | 該当する場合は警告バナー |
| アクションボタン | 「承認する」（プライマリ・大）／「差戻す」（セカンダリ） |

#### 7.9.3 ワンタップ承認のフロー

1. 「承認する」ボタンタップ
2. WebAuthn `navigator.credentials.get()` 呼び出し
3. OS生体認証ダイアログ表示（FaceID／指紋）
4. 認証成功 → 端末内秘密鍵で署名 → サーバへ送信
5. サーバが公開鍵で検証 → 承認確定 → ログ記録
6. 「承認しました」完了画面表示（5〜8秒で完結）
7. 申請者へ自動通知

#### 7.9.4 差戻し時のフロー

1. 「差戻す」ボタンタップ
2. コメント入力モーダル（必須）
3. 確認ダイアログ → 差戻し送信
4. 申請者へ通知

#### 7.9.5 デザイン上の留意点

- 金額は最も目立つ要素として配置（誤承認防止）
- 「承認する」ボタンには微細なパルスアニメーションで視認性を上げる（過剰にしない）
- 添付書類は1タップで全画面プレビュー可能に
